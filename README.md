## О проекте

**Bond Portfolio Analyzer** — интерактивное веб-приложение на Streamlit, решающее задачу **автоматизированного подбора портфеля рублёвых облигаций** среди ~2100 выпусков на Московской бирже.

### Что делает проект

1. **Загружает актуальные котировки** с MOEX ISS (Московская биржа): цены, доходности, купоны, сроки — по всем рублёвым облигациям (доски TQCB и TQOB).
2. **Обогащает кредитные рейтинги** со smart-lab.ru (АКРА, Эксперт РА, НКР, НРА) — заменяет заглушку BBB на реальные рейтинги для ~1700+ корпоративных бумаг.
3. **Строит портфель** по одной из трёх стратегий (Ladder, Barbell, Wheel) с учётом:
   - бюджета и уже вложенных средств (из журнала сделок)
   - минимального кредитного рейтинга
   - целевой доходности (YTM)
   - максимального срока до погашения
   - лимита на одну бумагу (% от портфеля)
   - исключения амортизируемых выпусков (MOEX bondization API)
4. **ML-модель (RandomForestRegressor)** предсказывает «справедливую» YTM по структуре бумаги и вычисляет **дополнительную доходность** (EXCESS_YTM = фактическая YTM − прогноз). Внутри однородных групп (рейтинг × срок) выпуски ранжируются — это позволяет выбирать наиболее недооценённые.
5. **Визуализирует денежный поток** (купоны + погашение номинала по годам) с учётом налога (0% ИИС / 13% НДФЛ).
6. **Ведёт журнал сделок**: сохранение покупок, учёт уже вложенных средств, экспорт заявок в CSV.

### Зачем это нужно

- Ручной подбор облигаций среди ~2100 выпусков на MOEX трудоёмок и подвержен субъективности.
- Простая YTM не учитывает «справедливый» уровень доходности для конкретной структуры бумаги (срок, рейтинг, купон, цена, тип эмитента).
- ML-модель помогает отделить **переоценённые** бумаги от **недооценённых** и выбрать лучшие в каждой группе риска.

## Источники данных

### MOEX ISS (основной источник)

- **Доски:** TQCB (корпоративные), TQOB (ОФЗ)
- **Валюта:** RUB (FACEUNIT=SUR)
- **Поля:** ISIN, SHORTNAME, MATDATE, FACEVALUE, COUPONPERCENT, ACCRUEDINT (НКД), WAPRICE (средневзвешенная цена), EFFECTIVEYIELD (YTM)
- **Фильтрация:** только активные (STATUS=A) российские (ISIN начинается с RU) бумаги с датой погашения в будущем

**Расчёт грязной цены:**
```
DIRTY_PRICE_RUB = FACEVALUE × WAPRICE / 100 + ACCRUEDINT
```

### smart-lab.ru (опционально, по запросу)

- Парсинг реальных кредитных рейтингов (АКРА, Эксперт РА, НКР, НРА)
- Определение рейтинга по ширине прогресс-бара на странице облигации
- Результаты кэшируются в `data/rating_cache.json`
- Запросы с паузой 2–3 сек между ISIN и retry при временных ошибках

**Маппинг ширины прогресс-бара → рейтинг:**

| Ширина | Рейтинг |
|--------|---------|
| 100%   | AAA     |
| 95%    | AA+     |
| 90%    | AA      |
| 85%    | AA-     |
| 80%    | A+      |
| 75%    | A       |
| 70%    | A-      |
| 65%    | BBB+    |
| 60%    | BBB     |
| 55%    | BBB-    |
| <55%   | BB+ и ниже |

### MOEX bondization (амортизация)

- API: `iss.moex.com/iss/statistics/engines/stock/markets/bonds/bondization/{ISIN}`
- Определяет, есть ли у выпуска события амортизации номинала (не только финальное погашение)
- Результаты кэшируются в `data/amortizing_cache.json` (TTL: 24 часа)

## Стратегии портфеля

### 🪜 Лестница (Ladder)

Равномерное распределение бюджета по годам погашения (1, 2, 3, 4, 5 лет).

- **Цель:** стабильный поток погашений, снижение процентного риска.
- **Механизм:** бюджет делится на 5 равных частей, для каждого года выбирается лучшая бумага.
- **Плюсы:** предсказуемый денежный поток, реинвестирование при погашении каждой ступени.

### 🏋️ Гантеля (Barbell)

Инвестиции только в короткие (до 1.5 лет) и длинные (от 4 лет) бумаги.

- **Цель:** баланс ликвидности и фиксации высокой доходности.
- **Механизм:** по 25% бюджета на 2 лучшие короткие + 2 лучшие длинные бумаги.
- **Плюсы:** «короткий конец» даёт ликвидность, «длинный» — повышенную доходность.

### 🎡 Колесо (Wheel / Max Yield)

Жадный алгоритм: покупка самых доходных бумаг в рамках лимитов.

- **Цель:** максимальная доходность на заданном горизонте.
- **Механизм:** топ-8 бумаг по YTM, на каждую ~1/6 бюджета, остаток добивается лучшими доступными.
- **Плюсы:** максимизирует YTM портфеля, подходит для агрессивных инвесторов.

**Общие ограничения:**
- Максимальная доля одной бумаги (по умолчанию 20% от портфеля)
- Учёт уже вложенных средств (из журнала сделок)
- Фильтрация по минимальному рейтингу и максимальному сроку
- Исключение амортизируемых бумаг (опционально)

## ML-модель

### Задача

Оценить **«базовую» (справедливую) доходность YTM** по структуре облигации (срок, купон, цена, рейтинг, номинал, тип эмитента) и посчитать **дополнительную доходность** относительно модели:

```
Дополнительная доходность (EXCESS_YTM) = Фактическая YTM − Прогноз модели
```

Внутри однородных групп (класс рейтинга × корзина срока) выпуски **ранжируются** по EXCESS_YTM — это позволяет сравнивать кандидатов и выбирать наиболее недооценённые.

### Признаки

| Признак | Описание | Тип |
|---------|----------|-----|
| `YEARS_TO_MATURITY` | Срок до погашения (лет) | Числовой |
| `COUPONPERCENT` | Купонная ставка (%) | Числовой |
| `LASTPRICE` | Цена в % от номинала | Числовой |
| `RATING_SCORE` | Рейтинг-скор (0=AAA … 16=CCC) | Числовой |
| `FACEVALUE` | Номинал (₽) | Числовой |
| `IS_GOVERNMENT` | Флаг ОФЗ (1) / корпоративная (0) | Категориальный |
| `MOD_DURATION` | Модифицированная дюрация (годы) | Числовой |
| `COUPONS_REMAINING` | Число оставшихся купонных выплат | Числовой |

**Целевая переменная:** `YTM_PCT` — доходность к погашению (%).

### Архитектура модели

| Компонент | Описание |
|-----------|----------|
| **Алгоритмы** | `RandomForestRegressor` / `GradientBoostingRegressor` — GridSearch выбирает лучший |
| **GridSearch** | 5-fold CV, два независимых поиска, победитель по MAE |
| **Scoring** | Отрицательная MAE (минимизируем абсолютную ошибку) |
| **Масштабирование** | `StandardScaler` (Z-score нормализация) |
| **Валидация** | 80/20 train/test split (random_state=42) |
| **Финальная модель** | Обучена на **100% данных** с лучшим алгоритмом и гиперпараметрами |

### Процесс обучения

1. **Загрузка данных:** из `bonds_current.csv` через `load_bonds_data()`
2. **Preprocessing:**
   - Расчёт `LASTPRICE = DIRTY_PRICE_RUB / FACEVALUE * 100`
   - Инженерия признаков: `IS_GOVERNMENT`, `MOD_DURATION`, `COUPONS_REMAINING`
   - Фильтрация выбросов YTM: остаются только бумаги с YTM от 0% до 50%
3. **Разделение:** train 80% / test 20%
4. **GridSearch с 5-fold CV** — перебор двух алгоритмов с гиперпараметрами:

   **RandomForestRegressor:**
   ```python
   {
       'n_estimators': [100, 200, 300],
       'max_depth': [5, 10, 15, None],
       'min_samples_split': [2, 5, 10],
       'min_samples_leaf': [1, 2, 4],
   }
   ```

   **GradientBoostingRegressor:**
   ```python
   {
       'n_estimators': [100, 200],
       'max_depth': [3, 5, 7],
       'min_samples_split': [2, 5],
       'learning_rate': [0.05, 0.1, 0.2],
   }
   ```

5. **Выбор победителя:** лучший алгоритм по CV-score (neg_MAE)
6. **Оценка** на тестовой выборке (R², MAE)
7. **Обучение финальной модели** на 100% данных с лучшими параметрами
8. **Сохранение артефактов:** `ml_model.pkl`, `ml_scaler.pkl`, `ml_metrics.json`

**Важно:** обучение выполняется **один раз** через `python src/ml_model.py` (~2–3 мин). 
При каждом расчёте портфеля модель **только загружается** из файла (миллисекунды) — переобучения не происходит.

### Ранжирование в группах

Выпуски делятся на однородные группы по двум критериям:

1. **Кредитный рейтинг:** AAA–A, BBB, BB и ниже
2. **Срок до погашения:** до 2 лет, 2–5 лет, свыше 5 лет

Внутри каждой группы выпуски ранжируются по **дополнительной доходности (EXCESS_YTM)**.

**Интерпретация:**
- **Ранг 1** — лучший кандидат в группе: рынок даёт наибольшую доходность сверх «справедливого» уровня → бумага недооценена
- **Ранг N** (последний) — бумага переоценена относительно аналогов

## Обработка датасета

### Этапы предобработки

Исходные данные — CSV с MOEX (~2100 строк рублёвых облигаций РФ).

1. **Загрузка и очистка колонок**
   - Имена колонок → верхний регистр, пробелы удаляются
   - Проверка обязательных полей: `ISIN, SHORTNAME, RATING, YEARS_TO_MATURITY, DIRTY_PRICE_RUB, YTM_PCT, COUPONPERCENT, FACEVALUE, MATDATE`

2. **Приведение типов**
   - Числовые поля через `pd.to_numeric`
   - Пропуски: `COUPONPERCENT → 0`, `FACEVALUE → 1000`

3. **Фильтрация**
   - Префикс ISIN = `RU` (только российские эмитенты)
   - `DIRTY_PRICE_RUB > 0` (торгуемые)
   - `YTM_PCT ≥ 0` (положительная доходность)
   - `YEARS_TO_MATURITY > 0` (непросроченные)
   - `MATDATE` не пропущена

4. **Расчёт признаков**
   - `LASTPRICE` = `DIRTY_PRICE_RUB / FACEVALUE × 100`
   - `RATING_SCORE` = текстовый рейтинг → числовой (0=AAA … 16=CCC)
   - `IS_GOVERNMENT` = ОФЗ (рейтинг AAA + имя начинается с «ОФЗ»)
   - `MOD_DURATION` = `YEARS_TO_MATURITY / (1 + YTM_PCT/100)`
   - `COUPONS_REMAINING` = число полугодовых периодов до MATDATE

5. **Фильтрация выбросов YTM (только для ML)**
   - YTM ограничивается **0–50%**
   - Аномальные значения (например, -99.98% или 60628%) не отражают рыночной ситуации
   - После фильтрации остаётся **~1770 строк**

### Итоговый датасет

| Параметр | Значение |
|----------|----------|
| Исходное число строк (MOEX) | ~2120 |
| После фильтрации (в `load_bonds_data`) | ~1830 |
| После обогащения рейтингами (корпоративные) | ~1123 |
| После фильтрации YTM [0, 50] для ML | ~1770 |
| Отсеяно выбросов | ~60 |
| Признаков для модели | 8 |
| Соотношение train/test | 80% / 20% |

## Метрики

### R² (коэффициент детерминации)

**Доля дисперсии YTM, объяснённая моделью.**

- 1.0 = идеальное предсказание
- 0.0 = модель предсказывает среднее значение
- <0 = модель хуже предсказания среднего

### MAE (средняя абсолютная ошибка)

**Среднее отклонение прогноза от фактической YTM в процентных пунктах.**

- Чем ниже, тем точнее прогноз
- Измеряется в тех же единицах, что и целевая переменная (п.п.)

### Текущие результаты

| Метрика | Значение |
|---------|----------|
| **R²** | **0.79** |
| **MAE** | **2.07 п.п.** |

**Динамика улучшений:**

| Версия | Алгоритм | R² | MAE |
|--------|----------|----|-----|
| v1.0 (базовая) | RandomForest | 0.71 | 2.80 |
| v1.1 (+признаки) | RandomForest | 0.77 | 2.22 |
| **v2.0 (текущая)** | **GradientBoosting** | **0.79** | **2.07** |

**Интерпретация:**
- **R² = 0.79** — модель объясняет **79% дисперсии** доходностей облигаций. Оставшийся 21% приходится на факторы, не учтённые моделью (рыночный спрос, ликвидность, макроэкономические условия, специфические риски эмитента).
- **MAE = 2.07 п.п.** — в среднем прогноз отклоняется от факта на 2.07 процентных пункта. Например, для бумаги с фактической YTM = 15% модель в среднем предскажет значение в диапазоне 15% ± 2.07 п.п.

**Что дало улучшение:**
- Переход от `RandomForestRegressor` к **автоматическому выбору** между RandomForest и **GradientBoostingRegressor** через GridSearch
- GradientBoosting строит деревья последовательно, исправляя ошибки предыдущих — это даёт более точные предсказания на табличных данных, чем усреднение деревьев в RandomForest

### Гиперпараметры (найденные GridSearch — победитель GradientBoosting)

| Параметр | Значение |
|----------|----------|
| **Алгоритм** | **GradientBoostingRegressor** |
| n_estimators | 200 |
| max_depth | 5 |
| min_samples_split | 5 |
| learning_rate | 0.2 |
| CV folds | 5 |

## Развёртывание

### Требования

- kubectl
- Доступ к Kubernetes-кластеру (локальный minikube / kind / облачный Managed K8s, например Yandex Managed K8s)

### Развёртывание

```bash
# 1. Развернуть все ресурсы одной командой
kubectl apply -f k8s/

# 2. (Опционально) Ingress — если требуется внешний доступ
kubectl apply -f k8s/ingress.yaml
```

### Проверка статуса

```bash
kubectl get all -n bond-portfolio
kubectl get pvc -n bond-portfolio
kubectl get pods -n bond-portfolio -w   # следить за инициализацией
```

### Доступ к приложению

- **ClusterIP (по умолчанию):** проброс порта для локального доступа
  ```bash
  kubectl port-forward -n bond-portfolio service/bond-portfolio-service 8501:80
  ```
  Приложение будет доступно по адресу `http://localhost:8501`.

- **Ingress (если настроен):**
  Добавьте в файл hosts (`/etc/hosts` на Linux/Mac или `C:\Windows\System32\drivers\etc\hosts` на Windows):
  ```
  127.0.0.1 bond-portfolio.local
  ```
  (или IP вашего ingress-контроллера) и откройте `http://bond-portfolio.local`.

- **NodePort / LoadBalancer:** измените `type: ClusterIP` на `type: NodePort` или `type: LoadBalancer` в `k8s/service.yaml`.

### Данные

PersistentVolumeClaim `bond-portfolio-data` монтируется в `/app/data` внутри контейнера. При удалении пода данные **сохраняются**. При удалении PVC данные теряются.

**Важно:** При первом развёртывании в пустом PVC необходимо один раз выполнить первичную настройку (загрузка котировок MOEX, парсинг рейтингов, обучение ML-модели) — см. раздел «Первичная настройка (один раз)» выше.

### Локальный запуск (без Kubernetes)

```bash
streamlit run app.py
```
